# 0001. มาตรฐานการพัฒนาและเพิ่มเติมเมนู/ฟังก์ชันในระบบ TextileOps CMMS

* **สถานะ (Status):** ยอมรับ (Accepted)
* **วันที่บันทึก (Date):** 2026-08-29
* **ผู้มีส่วนได้ส่วนเสีย (Deciders):** ฝ่ายวิศวกรรมบำรุงรักษา (Gemma Knits), ผู้ดูแลระบบ TextileOps CMMS

---

## 📌 บริบท (Context)

ระบบ TextileOps CMMS มีการขยายตัวอย่างต่อเนื่อง มีการเพิ่มเมนูย่อยและฟังก์ชันงานใหม่ เช่น การตรวจสภาพเข็ม (Needle Condition), การเช็คศูนย์เข็ม Single/Double Jersey (Center Check), การจัดการกระบอกเข็ม (Cylinders), และแผนการบำรุงรักษาเชิงป้องกัน (PM Plan) 

เพื่อให้ระบบมีความเป็นเอกภาพ ใช้งานง่ายบนทุกอุปกรณ์ (Desktop, Tablet, Mobile PWA) และมีความเสถียรสูงสุด จึงจำเป็นต้องกำหนดมาตรฐานสถาปัตยกรรมและ Checklist ที่ชัดเจนสำหรับการสร้างหรือแก้ไขเมนูทุกครั้ง

---

## 🎯 การตัดสินใจ (Decision)

เราตัดสินใจกำหนดมาตรฐานสถาปัตยกรรม 5 มิติสำหรับการเพิ่มหรือปรับปรุงเมนูในระบบ:

### 1. สถาปัตยกรรมข้อมูลแบบ Hybrid 3 ชั้น (Data Layer)
- **Supabase Cloud Database:** เป็นศูนย์กลางข้อมูลหลัก
- **Offline LocalStorage & JSON Fallback:** จัดเก็บข้อมูลสำรองเพื่อให้ระบบทำงานได้แม้สัญญาณขาดหาย
- **Google Sheets 2-Way Live Sync:** รองรับการซิงค์ข้อมูลออกเพื่อรายงานและทำเอกสารภายนอก

### 2. ชิ้นส่วน UI/UX 6 เสาหลัก (6 Core Pillars)
ทุกหน้าต้องมี:
1. การ์ดสรุป KPI สถิติด้านบน (4 ช่อง)
2. แถบ Action Toolbar (ค้นหา + กรองหลายมิติ + ซิงค์ชีต + ปุ่มเพิ่มข้อมูล/สแกน QR)
3. ตารางข้อมูลและ Responsive Card สำหรับหน้าจอมือถือ
4. ฟอร์มบันทึกข้อมูล Modal (พร้อม Field Validation + ตัวเลือก Preset + กล่องกรอก "ระบุเอง")
5. ลิ้นชักแสดงรายละเอียดเชิงลึก (Detail Drawer)
6. หน้าต่างพรีวิวเอกสารขนาด A4 และปุ่มพิมพ์ PDF (พร้อมลายเซ็น 4 ฝ่ายและ QR Code)

### 3. มาตรฐานการจัดการรูปถ่าย (Media Handling)
- ตรวจจับและแปลงรูปภาพ iPhone `.heic` เป็น `.jpeg` อัตโนมัติในระดับ Client ด้วย `heic2any` และ `normalizeImageFile`
- บีบอัดภาพไม่เกิน 1920px (คุณภาพ 85%) ก่อนอัปโหลด
- จัดเก็บภาพลงในโฟลเดอร์ Google Drive แยกตามชื่อเมนูอย่างเป็นระเบียบ

### 4. สิทธิ์การใช้งานและประวัติการทำงาน (Permissions & Audit Logging)
- ตรวจสอบสิทธิ์ด้วย `usePagePerms(module)` (`canAdd`, `canEdit`, `canDelete`) ตาม Role ของผู้ใช้งาน
- บันทึกการเพิ่ม, แก้ไข, ลบ ทุกรายการลงใน `AuditLogs` อัตโนมัติ

### 5. กระบวนการอัปเดตเวอร์ชันและ Deploy (Release Pipeline)
- อัปเดตเลขเวอร์ชันพร้อมกันใน 3 ไฟล์: `src/version.js`, `package.json`, `public/sw.js`
- ตรวจสอบการ Build ผ่านคำสั่ง `npm run build`
- Git Commit & Push สู่ GitHub Remote
- Deploy ขึ้น Vercel Production (`npx vercel --prod --yes`)
- มีปุ่ม `🔄 ล้างแคช & รีเฟรช` บนแถบเมนูด้านบนของเว็บ เพื่อแก้ปัญหา Service Worker แคชค้างบนอุปกรณ์ของผู้ใช้งาน
