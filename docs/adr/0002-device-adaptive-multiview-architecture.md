# 0002. สถาปัตยกรรมแยกการแสดงผลตามอุปกรณ์ (Device-Adaptive Multi-View Architecture: Mobile, Tablet, PC)

* **สถานะ (Status):** ยอมรับ (Accepted)
* **วันที่บันทึก (Date):** 2026-09-27
* **ผู้มีส่วนได้ส่วนเสีย (Deciders):** ฝ่ายวิศวกรรมบำรุงรักษา (Gemma Knits), ผู้ดูแลระบบ TextileOps CMMS

---

## 📌 บริบท (Context)

ในระบบ TextileOps CMMS หน้าจอเดิมใช้การแสดงผลแบบ Responsive รวมในไฟล์เดียว โดยเน้นตารางข้อมูล (Data Table) เป็นหลัก ส่งผลให้:
1. การเปิดใช้งานบนมือถือ (Mobile Smartphone) ช่างหน้างานต้องเลื่อนหน้าจอแนวนอน (Horizontal Scroll) ไปมา ทำให้อ่านข้อมูลและกดปุ่มแอ็กชันได้ยาก
2. หน้าจอแท็บเล็ต (Tablet / iPad) ซึ่งหัวหน้าช่างถือตรวจโรงงาน ไม่ได้ใช้ประโยชน์จากพื้นที่หน้าจอสัมผัสอย่างเต็มที่
3. เมื่อมีความต้องการปรับปรุงการจัดวางหรือขนาดฟอนต์บนมือถือ เสี่ยงต่อการทำให้หน้าจอคอมพิวเตอร์ (PC) ผิดเพี้ยนไปด้วย

เพื่อแก้ปัญหาดังกล่าว ผู้ใช้งานและทีมวิศวกรรมจึงตกลงร่วมกันในการแยกการแสดงผลระหว่าง **Mobile**, **Tablet** และ **PC** ออกจากกัน เพื่อให้สามารถปรับแต่ง UI ได้อย่างอิสระและตอบโจทย์พฤติกรรมผู้ใช้งานจริงในแต่ละอุปกรณ์

---

## 🎯 การตัดสินใจ (Decision)

เราตัดสินใจใช้รูปแบบสถาปัตยกรรม **Headless Logic Hook + Tri-View Presentation Components** โดยแบ่งออกเป็น 4 มิติหลัก:

### 1. การแยก Logic ออกจาก View (Headless Hook Pattern)
- รวมศูนย์ State, การดึง/บันทึกข้อมูล (D1 & Supabase), สิทธิ์การใช้งาน (`usePagePerms`), ตัวกรอง, ฟอร์มโมดอล และการสร้าง PDF ไว้ใน Custom Hook ประจำหน้า (เช่น `useMachinesLogic.js`)
- แต่ละ View Component ทำหน้าที่เฉพาะการแสดงผล (Pure Presentation) และรับ props/handlers จาก Hook เดียวกัน ทำให้ปราศจากความเสี่ยงเรื่อง Logic Drift หรือข้อมูลไม่ตรงกัน 100%

### 2. มุมมอง 3 ระดับเฉพาะอุปกรณ์ (Tri-View Presentation)
- **Mobile View (`*MobileView.jsx`):**
  - แสดงผลแบบ **Rich Card List** (การ์ดเดี่ยวแนวตั้ง มีรูปภาพ, รหัส Mc เด่นชัด, ป้ายสถานะ, สเปกเข็ม, วันที่ตรวจ)
  - แตะการ์ดเพื่อเปิด Detail Drawer / Bottom Sheet
  - มีปุ่มทางลัดด่วน (พิมพ์ PDF, แก้ไข, ลบ) ขนาดใหญ่พอดีนิ้วโป้ง
  - แถบค้นหาและฟิลเตอร์ติดตรึงด้านบน (Sticky Top)
  - ปุ่ม "+ เพิ่มข้อมูล" เป็นปุ่มลอย **Floating Action Button (FAB)** ที่มุมขวาล่าง
- **Tablet View (`*TabletView.jsx`):**
  - แสดงผลแบบ **2-Column Responsive Cards Grid** ใช้พื้นที่กว้างของแท็บเล็ตได้อย่างมีประสิทธิภาพ
- **Desktop View (`*DesktopView.jsx`):**
  - แสดงผลแบบ **Full High-Density Data Table** พร้อมปุ่มจัดการและ Toolbar แนวนอนครบถ้วน

### 3. ระบบตรวจจับขนาดจอและตัวจำลอง (Device Detection & Simulator)
- สร้าง Hook กลาง `useDeviceView()`:
  - **Mobile:** ความกว้าง `< 640px`
  - **Tablet:** ความกว้าง `640px - 1024px`
  - **Desktop / PC:** ความกว้าง `> 1024px`
- เพิ่มปุ่มสลับมุมมองจำลองบนแถบ Header:
  - `Auto` (ตรวจจับตามขนาดจอจริงอัตโนมัติ - ค่าเริ่มต้น)
  - `PC` (บังคับมุมมองคอมพิวเตอร์)
  - `Tablet` (บังคับมุมมองแท็บเล็ต)
  - `Mobile` (บังคับมุมมองมือถือ)

### 4. การจัดโครงสร้างไฟล์ (Feature Folder Pattern)
- จัดระเบียบโค้ดหน้าเพจเป็นโฟลเดอร์ เช่น `src/pages/machines/`:
  - `index.jsx` (Page Controller ดักจับอุปกรณ์และเลือก View)
  - `useMachinesLogic.js` (Headless Hook)
  - `MachinesDesktopView.jsx`
  - `MachinesTabletView.jsx`
  - `MachinesMobileView.jsx`

## 📈 ผลลัพธ์และข้อดี (Consequences)

- **Positive (อิสระในการปรับแต่ง):** สามารถปรับ Layout, สี, ขนาดตัวอักษร, ระยะขอบ ของมือถือได้อย่างอิสระ 100% โดยไม่ต้องกังวลว่าจะกระทบจอคอมพิวเตอร์
- **Positive (UX หน้างานดีขึ้น):** ช่างหน้างานและหัวหน้าช่างใช้งานผ่านมือถือและแท็บเล็ตได้อย่างคล่องตัว รวดเร็ว แตะปุ่มง่าย ไม่ต้องกวาดจอซ้ายขวา
- **Positive (ความปลอดภัยของข้อมูล):** ข้อมูลและการคำนวณใช้ Logic เดียวกัน ไม่มีความเสี่ยงที่บันทึกผ่านมือถือแล้วข้อมูลจะผิดพลาด
- **Mitigation (การควบคุมความซ้ำซ้อน):** บังคับใช้ Headless Hook เสมอ เพื่อห้ามเขียนคำสั่ง Database Query หรือ Form Validation ซ้ำซ้อนใน View Components
